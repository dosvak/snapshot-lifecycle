# Snapshot Lifecycle (SNAPLC) - process application

What depends on what, and can we go back: the toolkit dependency tree of every named application snapshot (toolkit, toolkit snapshot, system flag) as a table and an SVG tree - read from the product database because `/ops` exposes no dependencies - and a rollback advisor per container: every version with its running instances (`/ops` count), its open tasks (search), the active / default / tip flags and an advice line (drain or migrate the current version, re-activate an earlier idle version, archive an idle one).

Package `Snapshot-Lifecycle-1.0.twx` (generated by `tools/build_snaplc.py` on twxkit + kitlib, standard library only, no base export); targets: BAW 20.0.0.1+ (reports 8.6.2.20001), 24-26, CP4BA (/ops + product database).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API (and, where no
API exists, the product database read-only through the engine's datasource) with the technical user of the environment variables.

## Dashboard

| Tab | Content |
|---|---|
| Dependencies | application filter, all / active snapshots, Dependencies, Export CSV; SVG tree; table |
| Rollback advisor | container acronym, Advise; version table with advice |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows, REST calls and SQL

| Flow | Does |
|---|---|
| SC Dependencies | SQL: `LSW_PROJECT_DEPENDENCY` (NAME, TARGET_SNAPSHOT_ID, IS_SYSTEM) joined to the owning snapshot through `LSW_PO_VERSIONS` (BRANCH_ID + sequence range) and to the toolkit snapshot / project |
| SC Rollback Advisor | `GET /ops/std/bpm/containers/{acr}/versions`; per version `GET /ops/std/bpm/processes/count?containers=<acr>&versions=<v>&states=running`; `PUT /search/query` byTask open tasks of the container grouped by `instanceSnapshot` |
| SC Rows To CSV | dependency rows -> CSV |

Verified: 8.6.2.20001 lab: 139 dependency rows of 54 application snapshots (27 KB SVG tree), the 2 dependencies of HDLS 1.0; rollback advice for HDLT (one idle version, 16 open tasks on the unnamed tip reported) and BDSRCH (six idle versions). Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* `/ops/std/bpm/containers/{acr}?optional_parts=` accepts only `branches, versions` - toolkit dependencies exist only in the repository tables.
* Instances started from the designer run on the unnamed tip: `processes/count?versions=<name>` does not count them and the search rows carry an empty `instanceSnapshot` - the advisor reports them separately.
* A project dependency row is versioned like every repository object: the snapshot it belongs to is found through `LSW_PO_VERSIONS` by branch and sequence range, not by a foreign key.
